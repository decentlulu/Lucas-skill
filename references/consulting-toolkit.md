# 咨询工具箱

## 一、框架选择

| 问题 | 首选工具 | 关键提醒 |
|---|---|---|
| 发生了什么、为什么 | KPI 树、价值驱动树、5 Why、因果图 | 区分症状、机制与根因 |
| 在哪里竞争 | PESTEL、市场细分、五力、战略群组 | 明确市场边界和时间范围 |
| 如何竞争 | 客户价值主张、价值链、能力系统 | 竞争优势必须落到活动与取舍 |
| 如何增长 | 安索夫矩阵、三层面、邻接扩张 | 评估协同、能力缺口与风险递增 |
| 业务组合 | BCG/吸引力-能力矩阵 | 不把增长率和份额当作唯一尺度 |
| 组织是否匹配战略 | 7S、星型模型、组织能力诊断 | 架构只是组织的一部分 |
| 效率低在哪里 | SIPOC、流程图、精益浪费、约束理论 | 先找瓶颈，避免局部效率 |
| 如何变革 | 利益相关者图、变革故事、试点与反馈 | 同时处理损失、身份和能力 |
| 是否值得做 | 商业案例、NPV、情景与敏感性分析 | 说明口径、假设和替代方案 |

## 二、假设驱动分析

1. 写出决策问题和初始答案。
2. 将答案拆成可证伪的关键假设。
3. 按“影响 × 不确定性 × 验证成本”排序。
4. 为每项假设定义所需证据和判定阈值。
5. 优先验证可能推翻方向的假设。
6. 随证据更新议题树，不维护已经失效的故事。

MECE 是检查工具，不是现实世界必然互斥的声明。系统问题可用“主责归类 + 交互关系”避免重复计算又保留联系。

## 三、战略诊断

按以下链条判断：

`环境变化 → 客户/利益相关者需求 → 行业经济性 → 价值主张 → 活动系统 → 核心能力 → 经济结果`

检查：

- 市场定义是否过宽或过窄？
- 增长来自价格、数量、结构、留存、地域还是新品？
- 优势是暂时条件、资源禀赋，还是难以复制的活动系统？
- 方案是否明确“不做什么”？
- 核心业务现金流、成长业务规模化和未来期权是否平衡？

## 四、组织与运营模型

组织设计从价值创造和关键能力出发，依次回答：

1. 哪些战略任务必须被承接？
2. 哪些端到端流程创造价值？
3. 决策权与结果责任应放在哪里？
4. 需要怎样的结构、岗位、编制和协同机制？
5. 信息、预算、人才和激励如何流动？
6. 哪些能力必须建设、购买、借用或退出？

用 RACI/DACI 等工具明确责任，但避免把复杂协作简化成表格。每个关键决策必须有单一最终责任主体、输入方、执行方和升级机制。

## 五、效率、效能、效益

- **效率**：单位投入的产出。关注周期、成本、吞吐、利用率、返工和自动化。
- **效能**：目标实现和持续履职能力。关注质量、战略贡献、客户结果、协同与能力成熟度。
- **效益**：经济、社会、风险和长期价值的综合净结果。关注利润、现金流、资本回报、公共价值和韧性。

优化顺序通常是：删掉无价值事项 → 简化流程 → 消除瓶颈 → 标准化 → 自动化 → 重构机制。不要自动化无价值或错误的流程。

## 六、变革与落地

把方案分成四层：

- **方向**：变什么、为什么、成功是什么。
- **制度**：权责、流程、规则、资源和激励。
- **能力**：人员、技能、工具、数据与领导行为。
- **采用**：沟通、参与、试点、支持、反馈与强化。

实施计划必须包含：基线、目标、工作流、负责人、里程碑、依赖、风险、决策门、指标和复盘周期。优先做可逆的小规模验证，关键不可逆决策则提高证据门槛。

## 七、表达

- 用 SCQA 建立情境、冲突、问题和答案。
- 用金字塔原则结论先行、分组支撑。
- 每页/每节只传递一个主判断。
- 标题写成观点，不写成无信息量的主题词。
- 数据图表必须写明口径、来源、时间和结论。
